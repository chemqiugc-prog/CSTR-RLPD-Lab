## 2026-07-09 - CSTR 经济 reward 基线确认

**目标**

确认 CSTR 经济训练的基础 reward 是什么，作为后续所有 reward 改动的参照。

**涉及文件**

- `aiogym/env.py`
- `aiogym/train_rlpd.py`

**环境原始经济 reward**

CSTR 的经济收益来自 `AIOGymNativeEnv._economic_profit()`：

```text
profit = 产品价值 - 能耗成本 - 越界罚 - 失控罚
```

在 CSTR 下当前参数是：

```text
产品价值 = 1575.0 * production
能耗成本 = 0.7 * energy_kw
越界罚 = 14.0 * violation
失控罚 = 50.0, 仅 runaway 时扣除
```

训练环境中 `reward_mode="economic"` 时：

```text
env_reward = profit * reward_scale
默认 reward_scale = 0.03
```

**解释**

这条 reward 鼓励模型提高产量，同时控制能耗和温度越界。它本身不是强安全 reward，更偏经济优化，所以官方 RLPD 在正常工况下收益高，但在换热器/冷却失效时容易继续追产量，导致温度失控。

## 2026-07-09 - 风险门控蒸馏模型

**目标**

训练一个能看到风险特征的 13 维 CSTR 策略，让它学习 hybrid expert 的行为。

**涉及文件**

- `aiogym/train_cstr_risk_gated.py`
- `frontend/models/rlpd_cstr_riskgated.onnx`

**改动类型**

训练数据和模型输入改变，不是 reward 公式改变。

**训练方式**

1. 用官方经济 RLPD + late safety shield 组成 hybrid teacher。
2. 在正常 episode 和冷却故障 episode 中采集 teacher 轨迹。
3. 输入从官方 5 维扩展为 13 维，加入温升、预测温度、风险等安全特征。
4. 用监督学习/行为克隆训练 `RiskGatedNet`。
5. 输出仍是 2 维：

```text
action[0] -> 反应器温度设定点, 映射到 45..90 C
action[1] -> 进料泵目标, 映射到 0..1
```

**损失函数**

行为克隆 MSE：

```text
loss = weighted_mse(model(obs_13d), teacher_action)
```

风险样本、故障样本和高温样本权重更高。

**结论**

这个模型安全性比官方纯经济 RLPD 好，但正常工况产量和 profit 不够高，说明只靠模仿保守 teacher 容易把经济性也学保守。

## 2026-07-09 - RLPD 微调 reward ablation

**目标**

回应“reward 太复杂，导致安全情况下产量提不上去”的问题，把 reward 拆成几种简单版本做对照。

**涉及文件**

- `aiogym/train_cstr_risk_gated_rlpd.py`
- `aiogym/eval_cstr_reward_ablation.py`
- `docs/cstr_reward_ablation_results_2026-07-09.md`

**模型输出**

- `aiogym/runs/rlpd_cstr_ablate_profit_trip.onnx`
- `aiogym/runs/rlpd_cstr_ablate_temp_soft.onnx`
- `aiogym/runs/rlpd_cstr_ablate_pred_soft.onnx`
- `aiogym/runs/rlpd_cstr_ablate_smooth_gate.onnx`

**共同训练流程**

1. 先收集 prior data：正常 episode + 冷却故障 episode。
2. 使用风险门控 teacher 生成动作。
3. 对 actor 做 BC warm-start。
4. critic 做离线预训练。
5. 再做在线 RLPD 更新。
6. 训练中同时评估正常和故障工况，按综合 checkpoint score 保存最优版本。

**reward 版本 A：`profit_trip`**

最简单经济 reward：

```text
reward = 0.05 * profit - 8.0 * trip
trip = 1 if feed_trip or T > 92 else 0
```

含义：正常时只看经济收益，只有跳闸/超 92 C 才重罚。

**reward 版本 B：`temp_soft`**

加入当前温度软约束：

```text
over88 = max(0, T - 88)
reward = 0.05 * profit - 0.12 * over88^2 - 8.0 * trip
```

含义：温度超过 88 C 后开始提前罚，不等到跳闸才罚。

**reward 版本 C：`pred_soft`**

加入短期预测温度软约束：

```text
pred_T = T + dt * max(0, dTdt)
pred_excess = max(0, pred_T - 88)
reward = 0.05 * profit - 0.12 * pred_excess^2 - 8.0 * trip
```

含义：如果温度正在快速上升，即使当前还没超温，也提前扣分。

**reward 版本 E：`smooth_gate`**

分策略 reward：低风险偏经济，高风险偏安全。

风险值：

```text
risk = max(
  (T - 86) / 8,
  (pred_T - 89) / 8,
  (dTdt - 0.22) / 0.6
)
risk clipped to 0..1
T > 88 or pred_T > 90 时 risk 至少 0.65
feed_trip or T > 92 时 risk = 1
```

经济项：

```text
monitor = 0.04 * over88^2 + 0.12 * pred_over^2 + 0.15 * rise^2
economic_reward = 0.05 * profit - 0.05 * monitor
```

安全项：

```text
safety_cost =
  0.12 * over88^2
  + 0.48 * over92^2
  + 0.60 * rise^2
  + 0.45 * risk * pump^2
  + 8.0 * trip
```

最终 reward：

```text
reward = (1 - risk) * economic_reward - risk * safety_cost - 0.01 * action_smoothness
```

**评估结论**

100 episode 对比中，A/B/C 的最佳 checkpoint 相同，说明训练没有找到比 BC warm-start 更好的策略。E 的正常产量略高，但 KPI 和故障超温变差。

总体结论：reward 简化是对的方向，但单纯删安全项并不能自然超过 PID；策略仍容易在“正常追产量”和“故障保护”之间互相牵制。

## 2026-07-09 - residual_v9 前端采纳：保持官方正常收益，故障时尽量安全

**背景**

用户进一步明确目标：

```text

我们的目标不是正常工况超过官方，而是在尽量保持官方正常水平的情况下提高安全性。
```

因此策略目标从 `residual_v2` 的“安全优先”调整为：

```text
正常/轻扰动: 尽量等于官方 RLPD
明确失冷证据: 接管限泵/降温
接近跳闸边界: 软限泵
```

**涉及文件**

- `aiogym/eval_cstr_policies.py`
- `frontend/js/sim/controllers.js`

**核心变化**

新增并评估：

- `residual_v5`: 正常几乎完全放行官方动作，但故障接管太晚。
- `residual_v6`: 使用 v2 早期 latch，但正常误判严重，退化接近 v2。
- `residual_v7`: 使用 `obs_dTdt - model_dTdt` 失冷残差检测，正常收益接近官方，但故障仍偏晚。
- `residual_v8`: 更早触发失冷残差检测，故障更安全，但正常收益损失增大。
- `residual_v9`: 在 v8 和 v7 之间折中，最终前端采纳。

**residual_v9 逻辑**

`residual_v9` 不再简单用“温度高/温度在升”判断风险，而是重点看：

```text
residual_d = 观测温升 obs_dTdt - 模型预测温升 model_dTdt
```

直观含义：

```text
如果模型认为当前冷却指令应该能压住温度，
但真实温度仍明显上升，
则更像换热器/冷却失效，而不是正常贴边高产。
```

触发条件：

```text
cooling > 0.78 且 T > 60 且 residual_d > 0.055
或 cooling > 0.88 且 T > 65 且 residual_d > 0.035
或 cooling > 0.80 且 T_pred > 78 且 residual_d > 0.050
或 T > 60 且 residual_d > 0.120
```

latch 后：

```text
T > 68 或 T_pred > 72 或 obs_dTdt > 0.05 -> 关闭进料泵
否则 -> 泵开度上限 0.20
冷却拉满
温度设定点上限 68 C
```

接近跳闸边界时：

```text
T > 90.5 或 T_pred > 91.3 -> 连续软限泵
T > 92 -> 关闭进料泵，冷却拉满
```

## 2026-07-23 - P2.4 非线性预测风险屏障 Reward V1

**状态**：`完成；安全有效但经济性不足，不采纳、不替换前端`

### Reward 改动

- 新增独立可选模式 `economic_risk_barrier`，原 `economic` 默认行为保持不变。
- 经济主体仍为产品收益减冷却成本、88°C软罚和92°C失控罚，没有改写利润口径。
- 使用真实釜温、真实温升率和夹套升温率构造预测温度：
  `Tpred = T + 5*max(dT/dt, 0) + 2*max(dTj/dt, 0)`。
- 预测温度经 `softplus((Tpred-85.5)/1.0)^2` 形成平滑非线性屏障，权重为2.0；
  风险下降获得权重1.0的恢复反馈，单步限幅5.0；真实温度超过92°C额外扣100。
- Reward不直接奖励冷却开度，避免策略通过持续高冷却或先制造风险再恢复来获取动作奖励。
