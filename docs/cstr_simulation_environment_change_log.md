# CSTR 仿真环境更新日志

本日志只记录 CSTR 仿真环境、扰动模型、仪表执行器模型和环境验证方法的变化。强化学习网络、reward 和安全策略的变化继续记录在 `docs/cstr_model_change_log.md`。

## 当前版本

- **最新环境**：`industrial_p4`（前端标识 P2.4）。
- **更新时间**：2026-07-16。
- **当前状态**：P2.4已通过最低充分真实性审计并冻结；不再按“越复杂越真实”的方式继续增加机理。
- **算法边界**：本轮没有修改 reward、ONNX、控制器或安全保护参数。
- **校准等级**：参数来自工程先验，尚无真实装置数据，不能把 P2.4 称为经过工业验证的数字孪生。

## 记录规则

每次修改至少记录：

- 日期、环境版本和状态。
- 修改的方程、状态、参数、扰动或故障机制。
- 修改原因和物理假设。
- Python 与前端受影响的文件。
- 新增或更新的验证测试。
- 对旧策略、观测维度、动作接口和历史跑分可比性的影响。
- 尚未解决的限制。

状态使用以下标签：

- `已实施`：代码和必要测试均已完成。
- `实验中`：已有代码，但参数或验证尚未定型。
- `仅方案`：尚未修改仿真代码。
- `已回退`：曾实施但不再使用，并记录回退原因。

## 2026-07-14 - P2 工业现实性配置第一批

**基础环境版本**：`cstr_v2_jacketed`

**配置名称**：`industrial_p2`

**状态**：`实验中`

### 修改内容

- 新增 Python 仪表模型：延迟、一阶惯性、噪声、偏置漂移和量化。
- 新增执行器模型：行程时间、死区/静摩擦、量化和饱和。
- RL 与 PID 使用相同的延迟测量，物理积分、reward 和联锁仍使用真实状态。
- 新增带时间相关性的进料温度与冷却公用工程正常波动。
- `utility_stress` 同时导致冷却水升温和循环能力下降。
- 参数随机化由独立宽范围改为相关工况族：正常60%、高反应性原料20%、结垢
  15%、公用工程受限5%，避免多个低概率极值无条件同时出现。
- UA 结垢、原料批次和公用工程事件改用平滑形成过程，不再是纯瞬时阶跃。
- P1 环境保持默认 `ideal` 配置，历史模型和跑分不被覆盖。
- `train.py` 与 `train_rlpd.py` 增加 `--realism-profile industrial_p2`。

### 初始审计

30 episode P2 混合场景中，PID 为 0 次越界；纯经济 RLPD 有 29/30 回合越过
88°C；P1 前瞻安全版有 10/30 回合越界、4/30 回合跳闸。说明 P1 固定故障
矩阵不足以代表加入仪表与执行器动态后的安全性。

后续增加了独立高高温联锁：真实釜温达到 `92°C` 时锁存停料并全开冷却，
降至 `89°C` 后复位。联锁独立于 PID/RL，不作为控制器安全能力计分。

P2 专属 PID、12,000步 RLPD 和保守安全下限 `p2_f` 已建立。100 episode 中，
`p2_f` 最坏峰温为 `86.27°C`，零越界、零跳闸，利润为 `-7.35 ¥/h`；P2
整定 PID 利润为 `-19.72 ¥/h`。详细结果见 P2 报告和模型日志。

相关工况族启用后重新建立基线：P2整定PID利润 `-11.16 ¥/h`；P1官方式经济
模型利润 `8.18 ¥/h` 但100/100越界。官方主体加82°C包络和最小晚期保护后，
利润 `1.43 ¥/h`、产量 `17.00 mmol/s`、最坏峰温 `87.31°C`，100 episode
零越界、零跳闸。该策略没有改变环境reward。

### 验证

- P2 专项测试覆盖接口、种子复现、执行器速率、渐进结垢、相关公用工程事件
  和测量非直通特性。
- 详细参数、结果和限制见 `docs/cstr_p2_industrial_realism_report.md`。

- 前端 P2 等价实现和轨迹一致性测试尚未完成。
- P2 正式 PID/RLPD 基线尚未建立。

## 2026-07-13 - P1 显式夹套 CSTR 环境

**环境版本**：`cstr_v2_jacketed`

**环境名称**：`cstr_jacketed`

**状态**：`已实施`

### 问题边界

- P1 是原强放热抽象 CSTR 的机理升级，不定义具体化学反应。
- 乙酸乙酯皂化是独立新问题，未来使用单独的 `cstr_saponification` 环境，不受旧环境状态、动作、reward 或联锁标准限制。
- `cstr_v1_legacy` 保持不变，以继续复现历史 PID/RL 结果。

### 修改内容

- 新增四状态模型 `[Ca, Cb, T, Tj]`。
- 显式引入反应器/夹套体积、密度、热容、反应焓、UA、进料和冷却流量。
- 产量改为出口目标产物流率 `F/V*Cb`。
- 新环境基础观测为 8 维，额外包含 `Ca、Cb、Tj`。
- 新增冷却水入口升温、冷却循环损失和 UA 结垢故障。
- Python 动态环境会随机注入三类夹套扰动。
- 新环境已加入 Gym 注册、通用 SAC/RLPD 训练入口和前端场景选择器。
- 前端缓存版本更新为 `v=35`。

### 名义点

- `T=60°C`、进料开度 `0.5` 时：`Ca=0.117710 mol/L`，`Cb=0.882290 mol/L`。
- 夹套稳态温度为 `34.932°C`，所需冷却开度为 `0.264221`。
- 旧环境同点冷却开度为 `0.263499`，名义控制难度基本对齐。
- 初始状态改为该四状态名义稳态，并为 PID 增加 `0.264221` 稳态冷却偏置。
- P1 专属 PID 整定为 `Kp=0.20, Ki=0.01, Kd=0`。
- 20 episode × 6 工况均无 `T>88°C` 或联锁；正常温度 MAE 为 `0.171°C`，UA 下降 50% 时为 `4.115°C`。

### 验证结果

- P1 专项测试：`5 passed`。
- 通用环境接口测试：`4 passed`，另有 oracle 测试未在本轮执行。
- Python/JS parity：`cstr_jacketed max|Δ| = 0.00e+00`。
- 旧 `cstr` parity 继续通过：`max|Δ| = 7.11e-15`。
- JavaScript 语法检查和 Python 编译检查：通过。

### 兼容性影响

- 新环境观测空间为 8 维，旧 CSTR ONNX 模型不可直接使用。
- 动作空间仍为进料和冷却两个动作；监督模式仍为温度目标和进料目标。
- 新环境暂时沿用旧经济权重以便结构对照，但必须重新建立专属 PID/RL 分数基线。
- v1 文件、参数和历史跑分均未改变。

## 2026-07-13 - 建立环境基线与升级路线

**环境版本**：`cstr_v1_legacy`

**状态**：`仅方案`；本次建立基线文档和升级路线，物理方程未修改

### 当前环境快照

- 状态：`[Ca, T]`。
- 动力学：一阶不可逆 Arrhenius 反应。
- 进料：泵开度线性映射为稀释率 `D`。
- 冷却：冷却开度线性缩放等效移热项，冷却介质温度固定。
- 随机工况：`Uc`、`k0`、`Hr` 按回合独立缩放。
- 动态扰动：冷料温度、环境温度、需求和设定点台阶。
- 前端现实层：测量延迟/惯性/噪声/漂移/量化，以及执行器速率、死区和量化。
- Python 训练环境：具有简单观测噪声，但尚未完整复现前端现实层。
- 数值积分：固定微步长 RK4，CSTR 微步长 0.01 秒。
- 一致性：Python 轨迹通过 golden trajectory 与浏览器模型比较。

### 本次新增文档

- `docs/cstr_simulation_environment_upgrade_plan.md`
- `docs/cstr_simulation_environment_change_log.md`

### 审计结论

当前模型适合演示 Arrhenius 热失控和基础控制算法比较，但不足以证明策略对真实 CSTR 的普适性。最重要的缺口是冷却夹套无动态状态、参数单位未完全显式化、化学选择性缺失，以及 Python 训练环境与前端仪表执行器现实层不一致。

### 推荐下一版本

建议新增而非覆盖 `cstr_v2_jacketed`：状态升级为 `[Ca, Cb, T, Tj]`，使用显式物料/能量衡算和夹套动态，并保留现有动作接口的兼容层。

### 历史结果兼容性

本次没有修改方程，因此现有 PID、官方 RLPD、`residual_v9` 和历史 100 episode 结果仍可复现。未来启用 `cstr_v2_jacketed` 后，必须单独建立新环境基线，不能把 v1 与 v2 的绝对得分直接视为同一基准。

### 未解决事项

- 尚无真实设备参数和历史数据用于校准。
- 尚未建立显式单位表、稳态扫描和守恒测试。
- 换热器故障仍是简化故障，而非夹套/冷却回路机理故障。
- Python 训练环境尚未包含完整仪表与执行器动态。

## 2026-07-14 - P2.2 物理包络审计与相关原料批次

**状态**：`已实施`

- 新增四状态夹套 CSTR 稳态与参数包络审计工具，覆盖名义、高活性进料、结垢、公用工程受限和故意构造的组合压力场景。
- 对5档进料×5档冷却进行解析稳态根搜索，并使用四状态 Jacobian 特征值检查局部稳定性；125个网格点均找到稳态，没有数值伪根或多稳态，最大物料残差 `3.47e-18 mol/L/s`，最大能量残差 `2.79e-9 W`。
- 审计显示：组合压力场景在进料不低于0.70时，即使100%冷却也无法在92°C处实现瞬时热平衡。该场景只用于参数外推压力测试，不进入训练概率分布。
- 修正 `feed_batch` 的因果关系：不再只改变进料温度，而是让同一批次方向平滑联动入口浓度（最大±6%）、表观动力学活性（最大±4%）和单位反应热（最大±2%）。正向高负荷批次同时更热、更浓、更活跃、略微更放热；负向批次相反。

## 2026-07-15 - P2.4 泵/系统曲线与有限冷却公用工程

**环境版本**：`industrial_p4`

**状态**：`已实施`

### 修改内容

- 保留 `industrial_p3` 作为P2.3回归对照，新增独立的 `industrial_p4`；前端工业CSTR切换到P2.4。

## 2026-07-16 - P2.4 最低充分真实性审计与冻结决定

- P2.4相对P2.3的中位运行时间比为 `1.048`，新增物理没有造成不可接受的训练仿真开销。
- 全部研究级审计项通过；工业验证项仍未通过，因为缺少真实装置时序、设备曲线和经过辨识的参数分布。

- 不继续加入冷却塔、多用户管网、汽蚀、水锤或更多隐藏状态。
- 只有真实数据指出系统性偏差、跨环境控制结论反转、现有审计失败，或新研究问题明确依赖某项缺失机理且能提供参数来源时，才重新修改环境。
